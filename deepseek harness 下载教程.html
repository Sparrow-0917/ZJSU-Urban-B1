DeepSeek Harness 操作手册

安装 · 启动 · 排错 · 清理 —— 一站式的 Windows PowerShell 操作文档

当前锁定版本：@deepseek-ai/dsh@0.1.7-alpha.1

一、前置条件

在开始之前，请确认你的电脑已安装 Node.js，版本要求为 ^22.19.0 或 >=24.0.0。

# 检查 Node.js 版本
node -v

如果版本低于要求，请前往 nodejs.org 下载安装最新 LTS 版本。

什么是 npx？ npx 是 Node.js 自带的包运行工具，可以临时下载并运行某个 npm 包，不需要全局安装。DeepSeek Harness 官方推荐用 npx 方式启动。

二、安装与启动

2.1 首次安装并启动

打开 PowerShell，运行以下命令：

npx --yes @deepseek-ai/dsh@0.1.7-alpha.1 web

首次运行会自动下载依赖包，需要稍等片刻。启动成功后，终端会输出类似地址：

dsh web: http://127.0.0.1:3080

浏览器会自动打开该地址，如果没打开，手动在浏览器输入即可。

2.2 为什么锁定 0.1.7-alpha.1 这个版本？

DeepSeek Harness 目前处于开发者预览版（Developer Preview）阶段，npm 上的版本更新较快，不同 rc / alpha 版本之间可能存在依赖不完整的情况（你之前遇到的 ETARGET 错误就是典型表现）。锁定一个已经验证可用的版本，可以有效避免每次启动时因拉取到不完整的新版本而失败。

2.3 常用启动参数

参数作用示例
--no-open启动时不自动打开浏览器npx --yes @deepseek-ai/dsh@0.1.7-alpha.1 web --no-open
--port 3081指定其他端口（默认 3080）npx --yes @deepseek-ai/dsh@0.1.7-alpha.1 web --port 3081
日常使用建议：直接运行上面的启动命令即可。如果想省事，可以在 PowerShell 里按 ↑ 方向键调出历史命令，或者创建一个 .bat 文件双击启动。

三、启动后的首次配置

Web UI 打开后，需要配置模型 API Key 才能正常使用：

  1. 点击左下角 Settings（设置） → Models（模型）。
  2. 在 DeepSeek 卡片中填入你的 API Key（从 platform.deepseek.com 获取）。
  3. 保存后无需重启，立即生效。
  4. 回到主页，选择一个工作区（Workspace）目录，即可开始给 Agent 布置任务。

四、常见报错与解决方法

4.1 ETARGET：找不到匹配版本

报错内容：

npm error code ETARGET
npm error notarget No matching version found for
@deepseek-ai/dsh-client-ui-sidebar-documentpreview@^0.1.5-rc.3.

原因：DeepSeek Harness 的 rc / alpha 版本采用分阶段发布，各子包上线时间可能不同步，导致依赖树无法完整解析。npm 镜像源（如淘宝源）的同步延迟也可能导致此问题。

解决方法：

# 方法一：指定一个已知可用的具体版本（推荐）
npx --yes @deepseek-ai/dsh@0.1.7-alpha.1 web

# 方法二：临时使用官方 npm 源安装
npx --yes --registry=https://registry.npmjs.org/ @deepseek-ai/dsh@0.1.7-alpha.1 web

# 方法三：清理缓存后重试
npm cache clean --force
npx --yes @deepseek-ai/dsh@0.1.7-alpha.1 web

4.2 EADDRINUSE：3080 端口被占用

报错内容：

Error: listen EADDRINUSE: address already in use 127.0.0.1:3080
Failed plugins (1): webserver (required)

原因：之前启动的 DSH 进程仍在运行，3080 端口没有被释放。这不是安装失败，说明你的 DSH 本来就在正常工作。

先做这一步：直接打开浏览器访问 http://127.0.0.1:3080。如果页面能正常打开，说明服务已经在运行，你不需要再启动一次，直接用就行。

如果确实想重启：

# 查找占用 3080 端口的进程 PID
Get-NetTCPConnection -LocalPort 3080 -State Listen | Select-Object OwningProcess

# 找到 PID 后，强制结束该进程（把 12345 替换为实际 PID）
Stop-Process -Id 12345 -Force

# 或者一步到位，自动结束所有占用 3080 的进程
Get-NetTCPConnection -LocalPort 3080 -State Listen | ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }

也可以换个端口启动，不关旧的：

npx --yes @deepseek-ai/dsh@0.1.7-alpha.1 web --port 3081
# 然后访问 http://127.0.0.1:3081

4.3 npm warn deprecated：包已弃用

报错内容：

npm warn deprecated node-domexception@1.0.0:
Use your platform's native DOMException instead

说明：这不是错误，只是一个提醒。某些依赖包在较新的 Node.js 环境中已被原生功能替代，npm 会提示你“已弃用”。不会影响程序安装和运行，忽略即可。

4.4 npm warn using --force

报错内容：

npm warn using --force Recommended protections disabled.

说明：这不是错误。因为你在命令中使用了 --force，npm 提示你“安全保护已被禁用”。命令已经正常执行，忽略即可。

五、清理与卸载

清理前必须做的事：先关闭正在运行的 DSH 服务（关闭命令行窗口或在窗口中按 Ctrl + C），否则文件可能被占用导致操作失败。

5.1 清理 npx 缓存（安全，推荐优先执行）

npx 会把每次运行的包缓存在本地，这是可以安全清理的部分。清理后下次运行会自动重新下载。

# 查看并删除 npx 缓存目录
$npxCachePath = Join-Path $env:LocalAppData "npm-cache\_npx"
Write-Host "npx 缓存路径: $npxCachePath"
if (Test-Path $npxCachePath) {
    Remove-Item -Path $npxCachePath -Recurse -Force
    Write-Host "npx 缓存已清理。" -ForegroundColor Green
} else {
    Write-Host "未找到 npx 缓存目录，无需清理。" -ForegroundColor Yellow
}

安全 不会影响任何已安装的程序或个人数据。

5.2 清理 npm 全局缓存（可选，释放空间）

# 查看缓存条目数量
npm cache ls --parseable | Measure-Object | Select-Object Count

# 清理整个 npm 缓存
npm cache clean --force

安全 只清理包的压缩缓存，不会卸载已全局安装的包。

5.3 查看 DSH 个人数据目录大小

$dshPath = "$env:USERPROFILE\.dsh"
if (Test-Path $dshPath) {
    $size = (Get-ChildItem $dshPath -Recurse -ErrorAction SilentlyContinue | Measure-Object -Property Length -Sum).Sum / 1MB
    Write-Host ".dsh 目录大小: $([math]::Round($size, 2)) MB"
    Write-Host "路径: $dshPath"
} else {
    Write-Host "未找到 .dsh 目录。" -ForegroundColor Yellow
}

5.4 彻底删除 DSH 个人数据（谨慎！）

重要警告：删除 ~/.dsh 目录会永久清除所有会话记录、配置、API 密钥，不可恢复。除非你确定以后不再使用 DSH，否则不要执行此操作。 
# 先备份（可选但强烈建议）
Copy-Item -Path "$env:USERPROFILE\.dsh" -Destination "$env:USERPROFILE\.dsh-backup" -Recurse

# 确认后删除数据目录
Remove-Item -Path "$env:USERPROFILE\.dsh" -Recurse -Force

危险 删除后无法恢复，请务必先备份。

5.5 清理总结

清理目标操作安全性影响
npx 缓存 删除 %LocalAppData%\npm-cache\_npx 安全 仅清理临时包，下次自动重下
npm 全局缓存 npm cache clean --force 安全 释放空间，不影响已安装包
DSH 个人数据 手动删除 ~/.dsh 目录 危险 丢失会话、配置、密钥，不可恢复

建议执行顺序：先清理 npx 缓存 → 如果空间仍紧张再清理 npm 全局缓存 → 第三步根据是否继续使用 DSH 决定，不要盲目删除 .dsh 目录。
